# Disks and impermanence

## Plain filesystems

The default path: `hardware-configuration.nix` contains `fileSystems."/"`,
`fileSystems."/boot"`, swap, and similar entries produced by the installer.
Edit only when you know the machine; remember the file is regenerated by
future `nixos-generate-config` runs. For a declarative layout, move to disko
and regenerate with `--no-filesystems` so only one source declares mounts.

## disko (declarative partitioning)

```nix
{
  disko.devices.disk.main = {
    device = "/dev/disk/by-id/<the-disk>";
    type = "disk";
    content = {
      type = "gpt";
      partitions = {
        ESP = {
          size = "512M";
          type = "EF00";                       # EFI system partition
          content = { type = "filesystem"; format = "vfat"; mountpoint = "/boot"; };
        };
        root = {
          size = "100%";
          content = { type = "filesystem"; format = "ext4"; mountpoint = "/"; };
        };
      };
    };
  };
}
```

- Refer to disks by `/dev/disk/by-id/…`, never `/dev/sdX` — enumeration order
  changes between boots.
- The NixOS module generates `fileSystems` from the tree.
- Apply modes: `destroy`, `format`, `mount`, `format,mount`,
  `destroy,format,mount` (the full wipe — **erases the disk**). Example:
  `sudo nix run github:nix-community/disko/latest -- --mode destroy,format,mount /tmp/disk-config.nix`.
  `--flake github:org/repo` reads `.diskoConfigurations` from a flake;
  `--dry-run` shows the plan.
- `disko-install` wraps partitioning plus `nixos-install` in one command —
  the usual path for a fresh local install.

## nixos-anywhere (remote install)

`nixos-anywhere --flake .#host root@target` SSHes in, kexecs a NixOS
installer when needed, applies disko, installs, and reboots. It **wipes the
target**; confirm the disk targets (by-id) before running. Requires SSH access
and, for some providers, `--kexec`/`--phases` tuning.

## Impermanence (erase-on-reboot)

Root is a tmpfs (or is wiped by a rollback command); persistent state lives on
a separate volume, declared with `environment.persistence`:

```nix
{
  boot.initrd.postDeviceCommands = lib.mkAfter ''
    zfs rollback -r rpool/root@blank   # or mount a tmpfs as /
  '';

  environment.persistence."/persist" = {
    enable = true;
    hideMounts = true;                  # hide the persistent mounts from GUIs
    directories = [
      "/var/log"
      "/var/lib/nixos"
      { directory = "/var/lib/private"; mode = "0700"; }
    ];
    files = [
      "/etc/machine-id"
      { file = "/etc/ssh/ssh_host_ed25519_key"; parentDirectory = { mode = "0700"; }; }
    ];
    users.alice.directories = [ "Documents" ];   # prefixed with the home dir
  };
}
```

Classic forgotten entries — each silently loses data on reboot:

- `/etc/machine-id` (identity; regenerated means journal discontinuity),
- SSH host keys (new identity every boot; fingerprint prompts),
- `/var/log` (logs vanish),
- application state directories you only remember when something breaks,
- the user's home contents (declare under `users.<name>` or persist the home
  directory separately).

Mechanics and traps:

- Directories are **bind-mounted**; files are bind-mounted or symlinked
  (`method = "auto" | "symlink"`). A file that must be written before the
  persistent volume is available does not work.
- All persistent **and ephemeral** volumes must be marked `neededForBoot` (or
  be available in stage 1), otherwise boot hangs before the bind mounts run.
- Ownership/permissions on a persisted path are set when the directory is
  first created; changing `mode`/`user` later has no effect until the
  directory is removed on the persistence volume.
- Home Manager users need the persistence HM module plus the NixOS module; a
  tmpfs `/home/<user>` avoids the `fuse: mountpoint is not empty` error.
- **Test in a VM and reboot it.** The failure mode is silent loss of a path
  you forgot, detected only after the wipe; boot, then check each path exists.

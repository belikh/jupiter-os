Overview

Over the last 7 days, the jupiter-os repository underwent a critical evolution. The codebase transitioned from early storage, networking, and sync configuration bootstraps to a highly unified kiosk profile layout. This refactoring culminated in the development and cutover to robcoterm, a native Rust and Slint-based Fallout-themed replacement for Cage/Chromium on the dashboard panels.

Kiosk System Architecture

Previously, individual kiosk hosts (Amalthea, Metis, Adrastea, and Thebe) suffered from configuration drift. The recent changes unified these hosts under a singular profile, modularized system attributes, and established robcoterm as a lightweight native client direct-rendering via linuxkms.

Extracted overlapping kiosk boilerplate into a shared tcxwave-kiosk.nix profile. Replaced bindsTo=cage-tty1 with partOf in touch-wake services.
Why it mattered: Swapping the systemd binding logic prevents the kiosk touch-wake daemon from silently crashing/stopping during runtime nixos-rebuild updates.
Touched: modules/desktop/tcxwave-kiosk.nix, modules/services/tcxwave-touch-wake.nix, hosts/amalthea/
2026-07-13 to 2026-07-14
RobCo Terminal Kiosk Cutover & TDD Report
Wrote a lightweight native Rust app (robcoterm) powered by the Slint UI framework to directly interface with Home Assistant via WebSockets. Deployed as native kms-noseat service on amalthea.
Why it mattered: Replaces heavy Chromium/Cage kiosk stacks with a single 11MB binary. Cuts memory overhead, secures WebSocket tokens from being logged, and ensures instantaneous interface refreshes.
Touched: apps/robcoterm/, modules/desktop/robcoterm-kiosk.nix, hosts/amalthea/configuration.nix

Key Technical Takeaways & Gaps

  • Performance: Moving kiosks from a full Chromium container to native Slint via the Linuxkms backend dramatically improved startup latencies and input response.
  • Safety: Secrets are read strictly at activation time instead of flake build time, avoiding plain-text exposure in the global Nix store.
  • Known Gap (Visuals): Visual verification of the dashboard widgets is currently unverified under headless QEMU/Weston runners due to screen resolution limitations. Hardware panel tests are required.
